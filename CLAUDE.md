# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Bare-metal firmware experiments for the Electrosmith Daisy Pod (Daisy Seed 3, STM32H750), built with libDaisy (hardware abstraction) and DaisySP (DSP building blocks). Both are vendored as git submodules under `lib/`. Don't edit the submodules.

Each experiment is a separate app in `apps/<name>/`, and all of them live on `main` (experiments are folders, not branches). Code shared between apps goes in `common/`. Current apps:

- `apps/grainfall/`: granular and micro-loop effects after the Hologram Microcosm. This is the default `APP`.
- `apps/tapeworn/`: lo-fi tape machine (after Chase Bliss Generation Loss MKII).
- `apps/driftnet/`: always-listening micro-looper and spatial effect (after Chase Bliss MOOD MKII).
- `apps/slowdrift/`: stereo ambient reverb (after Walrus Audio Slöer).
- `apps/wavebyte/`: 8-voice wavetable synth (after Waldorf Protein), built in stages (see its README's roadmap).
- `apps/starter/`: low-pass filter hardware check, and the template that `make new` copies.

Each app has its own `README.md` with its control table. The top-level `README.md` indexes the apps.

`web/` is a browser control surface and visualiser (plain HTML/JS modules, no build step, served by `make web` on localhost because Web MIDI needs a secure context). It talks to an app over USB MIDI SysEx with the protocol in `common/web_link.{h,cpp}`, mirrored in `web/js/protocol.js`: change both together. See `web/README.md`.

## Commands

```sh
git submodule update --init --recursive   # fresh clone only
make libs            # build libDaisy + DaisySP (once after cloning or after bumping submodules)
make web             # serve the web control surface (web/) on http://localhost:8000
make                 # build the default app -> build/grainfall/grainfall.{elf,bin,hex}
make APP=starter     # build another app -> build/starter/starter.{elf,bin,hex}
make all-apps        # build every app; run this after changing common/
make list            # list apps
make new APP=<name>  # copy apps/starter to apps/<name>
make clean           # remove one app's build dir; make clean-all removes build/
make DEBUG=1 OPT=-Og # debuggable build (run `make clean` first so all objects rebuild)

make program-boot            # once per Seed: install the Daisy bootloader (chip DFU mode: hold BOOT, tap RESET, release BOOT)
make APP=<name> program-dfu  # build if needed, then flash over USB into the bootloader's DFU window (tap RESET, then press BOOT while the LED pulses to hold it there)
make APP=<name> program      # flash via ST-Link/OpenOCD (BOOT_NONE apps only)
make openocd                 # GDB server (one terminal) ...
make APP=<name> debug        # ... then attach arm-none-eabi-gdb (another terminal)
```

There are no tests or linters. A successful build is the only check you can run locally. Use `make all-apps` when a change touches `common/`. Flashing needs the physical board, so leave it to the user unless they ask you to do it. At the end of a DFU flash, `dfu-util` prints `Error during download get_status`. This is expected, because the board resets as soon as flashing finishes.

Toolchain: Arm GNU Toolchain 15.3.rel1 (`arm-none-eabi-gcc`, on `PATH` via `~/.zshrc`), dfu-util and OpenOCD from Homebrew.

## Build system

The top-level `Makefile` sets a few variables, then includes `lib/libDaisy/core/Makefile`, which defines the build and flash targets. It adds `list`, `new`, `all-apps`, `clean-all` and `libs`. Override behaviour through those variables:

- `APP` selects the app (default `grainfall`). `TARGET` is the app name, and `BUILD_DIR` is forced to `build/$(APP)` with `override`, because libDaisy assigns it unconditionally.
- `CPP_SOURCES` is every `.cpp` in `apps/$(APP)/` plus every `.cpp` in `common/`, so new files need no Makefile edit. `common/` is on the include path. Object files are named by basename only, so file names must be unique across an app and `common/`.
- libDaisy's `program` and `debug` recipes hardcode `./build/$(TARGET).elf`. The Makefile symlinks that path to the app's ELF, so don't remove that rule.
- `apps/<name>/app.mk` (optional) holds per-app overrides and is included before libDaisy's Makefile. It should set variables only, not define rules.
- `CPP_STANDARD = -std=gnu++17` (libDaisy's default is gnu++14).
- `APP_TYPE` defaults to `BOOT_SRAM` (set after `app.mk` is included, so an app can override it): the Daisy bootloader, installed once with `make program-boot`, loads code into SRAM (480 KB). Globals go in the 128 KB DTCM, shared with the stack. Grainfall uses about 110 KB of it, mostly libDaisy's MIDI handlers, so keep new state small and put buffers in SDRAM. The stack grows down into what's left with no check; `common/stack_meter.h` (main.cpp only) paints the free space at boot and reports how much was never touched (wavebyte traces it on the web page). An app with `APP_TYPE = BOOT_NONE` goes in the 128 KB internal flash and overwrites the bootloader.
- `OCD_DIR` points at Homebrew's OpenOCD scripts.

## Firmware architecture

Every app's `main.cpp` follows the standard libDaisy pattern:

- `main()` initialises the `DaisyPod hw` global, sets the audio config (48 kHz, block size 4), initialises the DSP objects with `hw.AudioSampleRate()`, then calls `hw.StartAdc()` and `hw.StartAudio(AudioCallback)`.
- `AudioCallback` runs in interrupt context once per block. It calls `hw.ProcessAllControls()`, reads knobs and buttons (`GetKnobValue`, `button1.RisingEdge()`), then processes non-interleaved stereo (`in[ch][i]`, `out[ch][i]`). Keep it real-time safe: no heap allocation, no blocking calls, no `System::Delay`.
- The `while(1)` loop in `main()` handles slow, non-audio work: LEDs (`led1`/`led2.Set` followed by `hw.UpdateLeds()`).
- State shared between the callback and the main loop is held in plain globals.
- Apps with more parameters than knobs page them with `PagedKnobs` (`common/paged_knobs.h`): the encoder press calls `NextPage`, the callback calls `Update` each block, and `main()` calls `Latch` once before `StartAudio` so a knob does nothing until it moves.
- Buttons that do one thing on a tap and another on a hold go through `PressHold` (`common/press_hold.h`). Bypass crossfades with `BypassFade`, after a `Limiter` on dry + wet (both in `common/`). `SampleBuffer` (`common/sample_buffer.h`) is an interleaved stereo ring for SDRAM, power-of-two long.
- Presets go through `Presets` (`common/presets.{h,cpp}`), built on the app's web parameter list: each `weblink::Param` has a `store` tag (`kPreset`, `kGlobal`, or `kNone` for on/off and momentary state), and the app's `ParamRaw`/`SetParam` read and write values, so tagging a parameter is all it takes to save it. `main()` calls `Init` before `StartAudio` (it applies the saved globals, then the last preset), the callback calls `Select`/`Step`/`Save` (from the preset page, the last page, whose encoder turn selects and long press saves; program changes; the page's preset commands via `Handle`) and `Apply` each block, and the main loop calls `Poll`, which does all the flash work: an erase blocks for up to 0.4 s and makes the flash unreadable, so never touch it from the callback. Globals and the selected slot are saved 3 s after they settle. A factory reset (`Reset()`, or `Init(..., true)` when `FactoryResetHeld(hw)` from `common/factory_reset.h` sees both buttons held at power-up; driftnet also takes MOOD's CC 56) erases the app's region and puts back the defaults `Init` recorded before applying anything saved; `FactoryResetHeld` waits for the buttons to be let go, so call it before `StartAudio`. `PresetStore` (`common/preset_store.{h,cpp}`) keeps records of (name hash, value) pairs, one 4 KB sector each, in the app's 64 KB region of the last 1 MB of QSPI (`PresetRegion`: a new app takes the next number); `QspiFlash` (`common/qspi_flash.h`, main.cpp only) is the Seed's side. An app declares `PresetsFor<kNumParams> presets` (arrays sized to its list, up to `Presets::kMaxParams`, a sector's worth: 1020; 18 bytes a parameter in DTCM, so an app short of it declares a `PresetsMemory<kNumParams>` with `DSY_SDRAM_BSS` and a `PresetsIn` over it, as wavebyte does), and its web_view.cpp defines `kParams` `constexpr` with `static_assert(UniqueKeys(kParams, kNumParams))`, since keys are 16-bit hashes of the names and two alike would mix up values. The web link's parameter indices are 14 bits; a list's descriptions go out several to a message, and its state in runs of 256.
- DSP code doesn't include libDaisy, so it also compiles on the host for offline tests. Shared helpers (`Rng`, `Biquad`, `DcBlock`, `Clamp`, `SmoothCoef`, `FastSin`…) are in `common/dsp.h`, namespace `dsp`.

Memory: put large audio buffers (grain and delay lines) in the 64 MB external SDRAM with `DSY_SDRAM_BSS`, for example `float DSY_SDRAM_BSS buffer[48000 * 10];`. Internal RAM is small. Apps that read SDRAM per sample call `TuneSdramTimings()` (`common/sdram_timing.h`) right after `hw.Init`: libDaisy's row timings are far slower than the SDRAM part needs, and with every voice and tap in a different row, almost every cache miss opens a new row. Even so, count SDRAM reads when designing an effect.

Grainfall: `apps/grainfall/main.cpp` holds the hardware setup (it runs the Seed at 480 MHz with `hw.Init(true)`, as tapeworn does; starter uses the default 400 MHz), paged controls, buttons and the MIDI map (Microcosm's CCs and program changes). MIDI (Pod TRS and USB) is polled in the audio callback so clock ticks are timestamped to within a block. `GrainEngine` (`grain_engine.{h,cpp}`) runs the chain: `Hold` (`hold.h`) -> `SampleBuffer` (interleaved stereo, power-of-two, SDRAM) -> the current `Effect` -> `PostFx` (pitch mod, Space, resonant low-pass, volume). Space (`space.{h,cpp}`) is the Microcosm's reverb: four modes over `Plate` (`common/plate.{h,cpp}`, mono input, no shimmer), its lines (176 KB) in RAM_D2 through the `.heap` section as driftnet's are; a mode change fades out, empties the lines a little a sample (`Plate::Clear`), sets the new size and fades back in. Each effect (`effect.h`) is a scheduler that, once per block, starts and steers voices from the `VoicePool` (`voice.{h,cpp}`: slices of the buffer played as grains or loops, with envelope, rate, reverse, filter and bitcrush), using the tempo grid and onsets (`onset.h`, with `OnsetDetector` from `common/onset_detector.h`). `Tempo` (`common/tempo.{h,cpp}`) combines tap tempo with `MidiClock` (`common/midi_clock.{h,cpp}`). Effects decide how much of their output is fed back into the buffer (`Effect::Feedback`). Mosaic, Seq and Glide are in `fx_micro_loop.{h,cpp}`; Haze, Tunnel and Strum in `fx_granules.{h,cpp}`; Pattern and Warp in `fx_multidelay.{h,cpp}`, which work per sample in `Effect::Process` with `TapReader` delay taps (plain, pitch-shifted or reversed) and their own feedback from the last tap. The web page's view of grainfall (parameter list, hello and telemetry frames) is in `web_view.{h,cpp}`; `main.cpp` applies `set` commands in the audio callback, snapshots the engine there on request (`want_telemetry`) and sends from the main loop, which runs every 10 ms. Blocks, Interrupt and Arp are in `fx_glitch.{h,cpp}`; Interrupt passes the live input through its wet output in `Process` (scaled by `Params::through`, which `main.cpp` sets from Mix so dry plus pass-through adds up to unity) and ducks it during glitches, so at 100% Mix it truly interrupts.

Tapeworn: `apps/tapeworn/main.cpp` holds the hardware setup and paged controls, and MIDI (TRS and USB, read in the audio callback): no CC map, only program change 1-8 for presets (as on Generation Loss) and the web page's SysEx. Its web view (`web_view.{h,cpp}`) sends traces of tape speed and level and the saturator's X-Y loop, from `TapeEngine::GetProbe()`. `TapeEngine` (`tape_engine.{h,cpp}`) runs the chain, built from `Hysteresis` (Jiles-Atherton saturation, 2x oversampled), `Wow`/`Flutter` (`tape_wobble`), `TapeFailure` and `TapeModel` (EQ profiles).

Driftnet: `apps/driftnet/main.cpp` holds the hardware setup (480 MHz), three knob pages (one per MOOD column; the encoder turn sets that page's three-way toggle: wet mode, loop mode, routing), the two buttons (a press switches a channel on at once, a tap switches it off, a hold freezes or overdubs; LATCH makes holds toggle), MIDI on every channel for now (TRS and USB, polled in the audio callback) with MOOD's CC map in `HandleCc`, and the web link. All the control state (toggles, MOOD's hidden options and DIP switches, ramping, tempo and Synth Mode settings) is plain globals written only in the callback, by the Pod, `HandleCc` and the page's `SetParam`; presets hold the sound (program change 1-8 as on MOOD) and the hidden options and DIP switches are saved as globals. Each block it updates `Tempo` (`common/tempo.{h,cpp}`; TIME syncs only once `HasTempo()` or MIDI clock is followed, in note values scaled by the CC 53/54 clock divisions), `Synth` (`synth.{h,cpp}`: notes set the clock in semitones and gate the output) and `Ramp` (`ramp.{h,cpp}`: bounce, one-off ramps and expression move chosen knobs), then hands `DriftEngine::Params` to the engine. TRUE BYPASS (CC 55) applies only while both channels are off: `Params::listen` stops the looper recording and trails are dropped. `DriftEngine` (`drift_engine.{h,cpp}`) keeps the dry signal at 48 kHz and runs everything else in the CLOCK's domain (`common/clock_domain.h`): a phase accumulator ticks the core at 2k-64k (stepped, or any rate for SMOOTH and Synth Mode) on the input interpolated to the tick's instant, and interpolates the core's output back to 48 kHz. Every buffer counts core frames, so the clock sets loop and delay length and pitch. Each tick: `MicroLooper` (`micro_looper.{h,cpp}`, with its Env, Tape and Stretch players and its options) plays its loop, routing picks what the Wet Channel hears, the selected wet mode runs (`WetReverb`, `WetDelay`, `WetSlip` in `wet_{reverb,delay,slip}.{h,cpp}`, each with its SPREAD and CLASSIC behaviour; only one runs, and a change fades out, calls the new mode's `Reset()` and fades in), then TONE and LEVEL BALANCE, and the looper either records input + wet into its ring (listening) or overdubs clean input at the play head. `Reset()` doesn't clear a ring: it counts frames written since, and older frames read as silence (clearing in the callback overruns: newlib-nano's `memset` goes a byte at a time). The Reverb's line and diffusers are in RAM_D2 (237 KB of its 256 KB, via the linker script's `.heap` section), because it reads 16 taps a tick and SDRAM reads are slow; keeping them out of DTCM also leaves room for the stack beside the two MIDI handlers. Don't fill RAM_D2: newlib's `_sbrk` grows the heap from the end of `.heap` with no limit check, and the USB stack mallocs, so running past the end of RAM_D2 hard-faults. The web view (`web_view.{h,cpp}`) sends the loop as a buffer section whose first head is the loop itself (marked as a tap, with the clock as its rate); the page draws it with `web/js/views/loop.js`, which `web/js/apps/driftnet.js` supplies as its `View`.

If you change an app's control mapping, update the control table in that app's `README.md` and the header comment in its `main.cpp`. When adding an app, add it to the app table in the top-level `README.md`.

Wavebyte: the first synth rather than effect (the Pod's audio input is unused). `apps/wavebyte/main.cpp` holds the hardware setup (480 MHz, block size 16, unlike the other apps' 4: see below), eleven knob pages, each with a second layer under Shift (button 2: held, or tapped to latch), as on the Protein's panel: the knobs are `PagedKnobs` layers (`Layer()`; the envelope, LFO, mod matrix and FX pages have a pair per envelope, LFO or slot, chosen by the encoder turn, and the Character page has only one), switched with `SetPage` as page, Shift or envelope change, so a knob does nothing until it moves. Button 1 is Play (the play note, changed by turning the encoder while held). The Filter page's encoder turn with Shift sets the Dirt type. Knob parameters map to layers by `KnobOf()`: two per layer up to the mod matrix, whose slots have three (Source, Amount; Target under Shift, whose knob 2 is a mirrored copy of Amount), and the FX slots one (Type): the FX page's other knobs (Amount; with Shift, Param and Value, as on the Protein) show the effects' values, kept in `fx_values` rather than in a layer. `Mirror()` keeps a knob showing a value stored elsewhere in step both ways; `FlashFxPick()` flashes LED 2 with what knob 1 picks, as there's no display. Knobs that pick from a list (LFO shape, ratio, mode; mod source, target) are 0..1 across it (`SynthEngine::Pick`), formatted by name on the web page. MIDI on any channel (TRS and USB, polled in the audio callback): notes with release velocity, pitch bend, channel and poly pressure, the matrix's controllers, CC 120/123 all notes off, the fixed CC map (`kCcMap`, `HandleCc`), program change for presets, and MIDI clock into `Tempo` (common/tempo.h), whose beats per block drive Clocked LFOs (`SynthEngine::Clock`). MPE (a global setting on the web page): channel 1 is the master channel, other channels' bend (±48 semitones, none at Bend Range 0), CC 74 and pressure belong to their note, and a note is released on its own channel. Each block `MakePatch()` hands the knobs and choices, as 0..1 and indices, to `SynthEngine::SetPatch` (`synth_engine.{h,cpp}`), which maps them to units once per block into a `Voice::Frame` shared by the voices, and keeps the MIDI controllers (`mod::Controllers`, `mod_matrix.h`), the two global LFOs (`lfo.h`), voice allocation, Poly/Mono/Legato (letting go in Mono hands the voice to the highest key still held, a Protein quirk to keep), glide and sustain. `Voice` (`voice.{h,cpp}`) has two oscillators reading `Wavetables` (`wavetables.{h,cpp}`: 64 tables x 64 waves x 128 int8 samples, 512 KB in SDRAM, generated at boot from our own recipes, since the Protein's are Waldorf's; waves 61-63 are triangle, square, saw in every table) by nearest sample, stepping between waves (8-bit), or interpolated and crossfaded (Clean; `Run<kClean>` is the per-sample loop); `Dirt` (`dirt.h`: Static, Crackle, Geiger, Click, Bursts, Ring Mod); Flavour (per-voice drifts at the voice's own rates plus per-note offsets, on wave positions, cutoff, level and osc 1's pitch, the last scaled by Bend Range, a Protein quirk); the DAC model at the amp (quantised after the level, 12 down to 6 bits, with per-voice gain error and a crossover dead band); two LFOs of its own for Free Voice mode; its share of the 8-slot mod matrix (`Voice::Modulate`, first each block, so envelope sources are a block behind and can move the envelopes' own rates, which each voice then works out with `Adsr::Coefs::SetTimes`); `Adsr` (`adsr.h`, stepped per block, coefficients shared via `Adsr::Coefs`); and `VoiceFilter` (`voice_filter.h`: a ZDF ladder for LP 24 and its own state variable filter for LP 12 and HP, both self-oscillating past 0.8 resonance from a little built-in hiss, with cutoff coefficients from a table built by `VoiceFilter::Init`; or Drive, where cutoff is the amount and resonance the curve). Oscillator pitch uses `dsp::FastExp2`, and `SetPatch` recomputes envelope and glide coefficients only when they change. Each voice's control maths runs once per block, and with the matrix it outweighed the samples: at block size 4 a busy patch passed 70% CPU and glitched, so wavebyte runs at block size 16 (3 kHz control rate). Keep divides and transcendental calls out of the per-sample loop (the filters' loop solution and clip have none). After the voices, `FxChain` (`fx.{h,cpp}`) runs two effect slots (routing: dry, FX 1 > FX 2, FX 2 only; a type in one slot at a time, so values belong to the type: `fx_params.h` holds one flat list with each type's run). The nine effects are in `fx_effects.h`, each `Set()` once per block (units, coefficients) and `Process()` in place with no per-sample divides; a change of type or routing fades the slot out, `Start()`s the new effect and fades it in. Delay lines (`fx::Ring`) aren't cleared: they count what's been written since a reset and read silence before it. The reverb is `Plate` (in RAM_D2 with the chorus, flanger and look-ahead lines, `fx_fast`, via the `.heap` section, 205 KB of RAM_D2's 256 KB: don't fill it), emptied with `Plate::Clear` over a few blocks before it fades in; the delay's lines are in SDRAM. DTCM is at 90% (the two MIDI handlers are 74 KB of it), so put new state elsewhere. The roadmap in its README lists the stages still to come; keep the Protein's quirks.

Slowdrift: `apps/slowdrift/main.cpp` holds the hardware setup (480 MHz), four knob pages (the encoder turn sets each page's choice: mode, waveshape, width, trails), the two buttons (button 1 on/off with smart bypass: a press while off turns it on at once and, if held past 0.4 s, off again on release; button 2 Sustain while held, or in Dream a press toggles Freeze), and MIDI (TRS and USB, any channel, polled in the audio callback): its own CC map in `HandleCc` (the Slöer has none: knobs on 14-21, choices on 22-25 split 0-127 evenly, CC 64 as button 2 through `SustainSwitch`, on/off, Freeze and mono in on 102-104), and the web page's SysEx. `SlowEngine` (`slow_engine.{h,cpp}`) keeps the dry signal at 48 kHz; the reverb's input passes a gate (closed while off, for trails, and while frozen) and Rise's `Swell` (`swell.h`, triggered by `OnsetDetector`), then everything runs in a `ClockDomain` at Stretch's rate (48k down to 12k, set with `SetHz()`). Each tick: Dark's octave down (`PitchShift`, `common/pitch_shift.h`) joins the input, then `Plate` (`common/plate.{h,cpp}`, shared with grainfall's Space), a Dattorro plate whose settings (decay gain, damping, bandwidth, diffusion, predelay, modulation, input width, shimmer) all move freely per block; only its size needs an empty tank, and slowdrift never changes it, so nothing is ever cleared. Plate's output is unscaled (0.6 is about unity), so each caller sets its level. Light's shimmer shifts part of one tank half's cross-feed up an octave inside the loop, never into the input: fed back into the input it ran away, since the reverb's gain is large at long decays. Decay times are set for 48 kHz, so Stretch lengthens them. The `Lfo` (`lfo.h`, five shapes with a 4 ms slew) moves the tank's modulated allpasses; Dream's vibrato has its own `Lfo`. Then width (mid/side, level made up), the vibrato and the mode's low-pass. The plate, both shifters and the vibrato lines (201 KB) are in RAM_D2 through the `.heap` section. The web view (`web_view.{h,cpp}`) sends traces of the LFO, the input gain and the decay time from `SlowEngine::GetProbe()`.
